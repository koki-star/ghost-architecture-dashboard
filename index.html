Admin Editor

The browser interface where an author writes and manages posts. It communicates with Ghost through the Admin API over HTTP.

Architectural interpretation: a modular monolith at the core, with a separate browser admin client. Ghost Core handles APIs, server logic, and default theme rendering in one Node.js process. Its database is a separate persistence layer.

3. Sources and trade-off

A single core application simplifies coordination, but its internal modules share a process and are not independently scaled services. This is our interpretation of the documented runtime boundaries.

  • Ghost source: runtime architecture — process boundaries and theme rendering.
  • Ghost architecture documentation — APIs and storage. MySQL is recommended for production; SQLite is used for local development.

Scope: default theme-based publishing. Email, payments, caching, and optional external integrations are outside this small model.
